# ADR 002: Explicit memory files and branch-local declared todos

Accepted for the interactive-tools package.

Memory uses a single typed `memory` tool and bounded Markdown files. The global root is `getAgentDir()/memory`, defaulting to `~/.pi/agent/memory` and honoring `PI_CODING_AGENT_DIR`. Project operations and index injection require `ctx.isProjectTrusted()`; global memory remains available independently. Each call resolves the current session cwd anew (without walking ancestors): prefer `.agents/memory`, then an existing `.pi/memory`, otherwise create `.agents/memory`. Only `MEMORY.md` indexes (4 KiB each) enter the current turn's system prompt; topics (32 KiB each) require an explicit read. Index text is reference data, never authority. There is no discovery scan or implicit topic loading. Index maintenance is explicit using the same CRUD interface; deleting a topic does not silently rewrite its index.

Names cannot contain paths, hidden names or arbitrary extensions. Every case variant of `memory`/`memory.md` is reserved except the exact `MEMORY.md` index name, preventing topic/index collisions on case-insensitive filesystems. Pi schedules the memory tool sequentially, and an extension-local promise queue also serializes direct concurrent callbacks across the complete read/modify/write operation. A failed or cancelled operation does not poison later operations. This prevents same-instance lost updates and delete/update resurrection; separate Pi processes still require external coordination. Reads and writes reject symlinks, hardlinks, special files, invalid UTF-8, control characters, excessive sizes and recognizable credentials. Writes use mode 0600 and an exclusive temporary file followed by rename; directories use mode 0700. Normal write/rename exceptions clean up the temporary sibling in `finally`. Abrupt process termination can leave a mode-0600 temporary file; startup does not scan for or delete these files. Project writes exclusively create a memory-local `.gitignore` containing `*` when absent, which excludes the whole directory including the ignore file. Existing ignore files are preserved byte-for-byte and must end with a literal wildcard rule after blank lines and comments are removed; otherwise writes fail without changing their rules. This conservative check rejects configurations whose complete exclusion cannot be proven. Previously tracked files remain Git's responsibility; the extension does not untrack user files. The filesystem boundary protects against static path redirection, not a hostile same-user process racing directory replacement. Credential recognition is deliberately a high-confidence filter, not a promise to identify every secret. It applies on reads as well as writes: false positives such as illustrative credential assignments can reject a note or index. We fail closed and report the rejection instead of silently redacting or changing stored content.

Todos use the public session branch API and versioned custom entries, not a project file or full-session history. `todo_write` replaces a normalized list and permits at most one in-progress task. Restoration follows the selected branch on startup, resume, fork, reload and tree navigation. Each user turn persists the stale-turn count; reminders strengthen at three and six unchanged turns. Repeating an identical declaration does not reset that count. We retain per-user-turn custom-entry persistence to preserve the counter precisely across resume and tree navigation. The counter itself is never injected into the system prompt; reminder text changes only at the three/six-turn thresholds or when the declared list changes, avoiding per-turn prompt-prefix churn. Completion is only a tool caller's declaration, never inferred from assistant prose or tool activity. All-completed lists remain in history but clear the widget and reminders; `[]` clears the list. Invalid or future-version snapshots clear state rather than resurrecting obsolete progress.

Schemas use Pi’s `StringEnum` for provider compatibility. Tests exercise registered tools and lifecycle hooks with synthetic temporary homes and an explicit synthetic `PI_CODING_AGENT_DIR`, restoring both environment values afterward. The disposable sandbox harness additionally uses Pi's real SessionManager to prove disk resume, branch navigation and project-changing forks without provider calls or access to user memory.
