# Fast models and work-scoped power inhibition

## Status

Accepted. Fast mode and auto-caffeinate are both active.

## Decision

Each extension owns its Pi adapter and one implementation module. No shared integration framework is introduced.

`/fast [on|off]` switches between base and `~fast` model entries. Aliases exist only for the `openai` Responses path on api.openai.com and `openai-codex` Responses path on chatgpt.com. Installation skips providers with another extension's legacy registration to preserve its endpoint and authentication. A same-ID Provider wrapper wraps the registered native provider or the runtime builtin before models.json composition, so removing or updating base-model overrides takes effect on refresh. Pi 0.85.1 requires guarded access to the private `runtime.builtins` map to retain the pi.dev catalog overlay, with public `builtinProviders()` factories as the fallback when unavailable. The wrapper preserves authentication and model filtering, strips the alias before requests and passes `serviceTier: "priority"` into the original provider stream. Pi 0.85.1 streamSimple drops provider-specific options, so the wrapper uses Pi's exported base-option and reasoning helpers before dispatching to stream. The original provider computes usage costs, including its priority multiplier; alias metadata retains base rates to avoid charging the multiplier twice. Costs remain upstream estimates, not proof of entitlement or a billing receipt. No provider credentials are inspected or changed.

Alias lifecycle: eligibility and config-declared direct models are snapshotted from the configured provider view at installation. Builtin aliases use native metadata; no base-model overrides carry over to builtin aliases. Config-declared aliases retain their installation snapshot until restart. Reloads avoid duplicate wrappers. Resumed saved aliases are restored after session_start registration; Pi may first display its fallback-model warning because aliases are unavailable before that lifecycle event. Pi also selects a new session's model before that event, so session_start repeats Pi's choice for `/new` and sessions without context messages unless `--model` is given (Pi ignores `--provider` alone): an `enabledModels` or `--models` scope picks the saved default when in scope, otherwise its first entry, and without a scope the saved default applies. The alias is selected only when that choice is fast, with reasoning from `--thinking`, the scope entry, the per-model level, the default level, then Pi's `medium`. Pi still warns that fast scope entries match no model, and model cycling omits them because extensions cannot change the session scope. `--model provider/id~fast` uses Pi's custom-model fallback with a warning until registration replaces it with the alias. Registering during extension loading is not an alternative: Pi exposes no model registry to factories, and queued native registrations replace another extension's legacy registration of the same provider. Disabling this extension leaves saved aliases unavailable.

Auto-caffeinate starts no resources during extension loading. Agent start acquires inhibition only when the OS positively reports AC power. Agent settled starts a five-second linger, and background task IDs hold the inhibitor independently. The event contract is `pi-interactive:background-activity` with `{id: string, active: boolean}` on Pi's session event bus. The subagents integration emits these transitions; duplicate IDs are idempotent. Shutdown unsubscribes, waits for queued checks and reaps the child. Agent start and settled handlers return without waiting for a power check. Starting work reuses a power reading under five seconds old. While work is pending, a two-second watchdog recovers failed helpers and re-reads power every 30 seconds, so inhibition follows a switch between AC and battery within about 30 seconds. Linux ignores supplies with `Device` scope, such as wireless mouse and headset batteries; a power-supply directory with no other supplies is treated as a fixed-power desktop on AC. Battery, unknown state, a system battery without a mains reading, a missing power-supply directory and unsupported platforms never acquire an inhibitor.

Linux runs `systemd-inhibit --what=idle --mode=block` with a pipe-reading `/bin/cat` child. It adds `--no-ask-password` only when `systemd-inhibit --help` lists it, checked once per load and retried with the helper if the check fails: systemd 257 added the flag, and older releases reject it but never request interactive authorization. systemd-inhibit starts `cat` only after taking the lock, so the status shows Awake once `cat` echoes a probe line; a helper that exits early never shows Awake and is retried after 30 seconds. Closing the owner pipe releases it, including when the parent dies. macOS runs `/usr/bin/caffeinate -i -w PID`; `/usr/bin/pmset -g batt` detects power. Inhibitor failures are a no-op. These commands do not change persistent sleep settings. Linux desktop power reporting was empty on the inspected host and the restricted worker sandbox blocked system-bus access. An approved read-only host inhibitor listing succeeded; no host inhibitor was acquired, so actual host inhibition is not claimed. macOS process arguments and fixtures are not an actual Mac desktop smoke test. The systemd 255 container used for the flag fix has no system bus, so lock acquisition there was checked only up to the helper's arguments; the echo handshake was checked with a synthetic `cat` child.

## Verification

Tests exercise real built-in OpenAI serialization against an injected fetch response, all supported reasoning levels, request authentication, priority usage pricing, toggle/resume behavior, saved fast defaults and scopes in real new sessions, and provider isolation. Power tests exercise AC/battery/unknown state, peripheral batteries, linger, background tasks, cache/watchdog cadence, helper flag detection, early helper exit and real `/bin/cat` pipe cleanup without inhibiting the user's desktop.
